# Viewsource

**Extract reusable, production-quality components from real websites and GitHub repositories — with AI-assisted analysis, live previews, and copy-paste-ready code.**

## What it does

Viewsource turns a website or a codebase into a browsable catalog of its UI components. For each component you get a live preview, an AI-generated description with its real prop interface, a ready-to-use LLM prompt, and the full source.

Two ingestion paths feed the same public gallery:

- **From a GitHub repository** — the codebase is parsed at the AST level to identify exported React components, their typed props, and their internal dependency graph. Each component is rendered from the project's own dev server and captured as a real screenshot. Fidelity is 100% by construction: the code already exists, nothing is guessed.
- **From a live website** — a human-in-the-loop reconstruction flow (video capture → AI structural analysis → assisted rebuild) recreates a site's sections as faithful, parametrized components.

## Why it's interesting (the engineering)

This project is less about "another gallery" and more about a set of non-trivial problems solved pragmatically:

- **AST-based component extraction, not LLM guessing.** Components, prop interfaces, hooks, and the dependency graph are extracted deterministically with a real parser (Babel/TypeScript). The LLM is used only where judgment is needed — ranking components by relevance and describing them — not where precision is required. This makes extraction exact, repeatable, and cheap on tokens.
- **Multi-file component bundles.** A real component is never one file. By walking the dependency graph, Viewsource assembles the complete, working bundle (component + custom hooks + CSS modules + types + npm deps) — not an isolated snippet.
- **Preview via React fiber mapping.** Component previews are generated by running the target project's dev server and walking React's fiber tree (the technique React DevTools uses) to map each component instance to its DOM node and bounding box, then capturing a cropped screenshot. Works on dev builds where component names aren't minified.
- **A hard lesson in scope.** The site-reconstruction path started as a fully automated pipeline (capture → auto-slice → LLM rebuild → visual-diff loop). It didn't work: it mis-detected sections and burned tokens for unusable output. I rebuilt it around a human-in-the-loop studio flow where code lives as real files on disk (editable in any editor, iterable with AI, versioned in Git) and the database is only a published projection. Knowing when to abandon automation is part of the work.

## Architecture

| Layer | Choice |
|---|---|
| Framework | Next.js (App Router) + TypeScript |
| Styling | Tailwind CSS |
| ORM / DB | Prisma 7 + PostgreSQL (Neon) |
| Vector search | Qdrant (semantic search over ingested content) |
| AI | LangChain + LLMs with structured output (Zod schemas) |
| Static analysis | Babel / TypeScript Compiler API |
| Capture & preview | Playwright (headless, admin-side) |
| Auth | Admin: signed-cookie session · Public users: Clerk |
| Payments | Stripe Checkout (lifetime unlock per site) |
| Hosting | Vercel |

**Public / private split.** The heavy pipeline (repo cloning, dev-server execution, Playwright capture, AI analysis) runs admin-side and never on serverless — a deliberate architectural boundary. Vercel serves only the read-side and light on-demand generation. New sites are ingested locally against the production database.

## Key features

- Browsable public gallery of ingested projects and their components
- Per-component live preview, typed prop interface, and description
- Free LLM-ready prompt (with partial code snippets) for every component
- Full multi-file source, gated behind a one-time per-site unlock
- AST-driven extraction with dependency-complete bundles
- Human-in-the-loop reconstruction flow for live websites

## Running locally

```bash
git clone https://github.com/itsgigi/Viewsource.git
cd Viewsource
npm install

# start the local Qdrant instance
docker compose up -d

cp .env
npx prisma migrate dev
npm run dev
```

Environment variables:

```env
DATABASE_URL=           # PostgreSQL (Neon) connection string
QDRANT_URL=             # Qdrant instance
QDRANT_API_KEY=         # (if using Qdrant Cloud)
OPENAI_API_KEY=         # or your chosen LLM provider
FIRECRAWL_API_KEY=      # for crawling websites info & images
GITHUB_TOKEN=           # for cloning repositories
ADMIN_PASSWORD=         # admin access
AUTH_SECRET=            # session signing
BLOB_STORE_ID=          # for assets
BLOB_READ_WRITE_TOKEN=  #

# Clerk / Stripe keys as needed
```
